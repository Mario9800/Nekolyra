## 这是什么

Nekolyra 是一个跑在 QQ 群里的 AI 助手。它不只是"接个 API 回话"，而是：

- **有记性** —— 记住群里的事，也记住每个人说过的话；分群隔离，互不串
- **会说话** —— 接 IndexTTS，能按情绪用不同语气发语音
- **能管群** —— 入群验证、广告拦截、黑名单、签到积分、群报
- **能查资料** —— 带文件夹结构的知识库，问游戏设定、群规、常见问题都能答
- **能装插件** —— 抽奖、群报、签到、今日老婆都是插件，不要就卸掉；也能自己写
- **有管理界面** —— 不用改配置文件，浏览器里点点就行

打包成 Windows 程序，双击就能跑，**不需要装 Python**。

## 功能

### 🔌 插件系统

这是这个项目现在最核心的设计：**功能不再焊死在主程序里**。

主程序只留公共底座（AI、记忆、语音、知识库、群管、备份），
具体功能做成插件，装不装、开不开你说了算：

| 插件 | 干什么 |
|---|---|
| 抽奖 | 从最近活跃成员里随机抽一个并 @ 他 |
| 群报 | 群里某天的发言排行（26 个关键词别名） |
| 签到积分 | 每日签到拿积分、看排行、查自己的积分 |
| 今日老婆 | 抽二次元老婆（AI 写介绍 + 配图），可用积分换 |
| 打招呼 | 最小示例，照着它就能写自己的 |

- **管理界面里一键装卸** —— 「插件 → 插件市场」浏览、安装、更新、卸载
- **也能装任意 GitHub 上的插件** —— 贴仓库地址就行，不用等收录
- **改完代码点「重新加载」** —— 不用重启程序
- **插件能往界面里加东西** —— 自己的配置小窗、自己的管理页、自己的接口
- **自己写插件** —— 见 [插件系统](#插件系统)，或
  [nekoe-plugins](https://github.com/Mario9800/nekoe-plugins) 里的完整文档

> **插件页面不占侧边栏。** 装十个插件，侧边栏还是干干净净一项「插件」——
> 每个插件的入口都在它自己的卡片上。

### 🤖 AI 对话

| | |
|---|---|
| 多种后端 | 云端 API（OpenAI 兼容）或本地 Ollama，随时切换 |
| 上下文 | 可调保留轮数；群聊和私聊各自独立 |
| 主动发言 | 可设概率，让它在冷场时自然接话 |
| 打字节奏 | 可设间隔范围、长回复自动拆成多条，像真人在打字 |
| 视觉识图 | 群里发图，它能看懂内容再回 |
| 人格设定 | 名字 / 身份 / 行为准则 / 说话风格，四项自由填 |

### 🧠 长期记忆

这是花力气最多的部分。分成两层，**互不影响**：

```
群级记忆    整个群共享：群规、话题、共识
用户级记忆  只属于某个人，按群隔离
            （张三在 A 群的偏好，B 群看不到）
```

- **自动提取** —— 每 N 轮对话分析一次，从聊天里挑出值得记的
- **用户画像** —— 发言次数、活跃天数、积分、共处几个群，问"我是谁"能答上来
- **手动增删** —— AI 漏了的自己补一条；记错的当场删
- **原始发言** —— 每条记忆旁边能展开，看它是从哪句话得出来的
- **三层删除** —— 删单条 / 清空某人在本群 / 清空某人全部（跨群）

### 🔊 语音合成

接 [IndexTTS 2.5](https://github.com/index-tts/index-tts) 本地服务。

- **情绪音色** —— 识别回复里的情绪，自动切换对应音色（平静/喜/怒/哀…）
- **多语言** —— 中文 / 日语 / 英语按文本自动选音色
- **发音词典** —— 生僻字、专有名词可指定读音
- **音频后处理** —— 去刺音、提清晰度、变温暖
- **自然度调参** —— 语速、采样温度、束搜索宽度、句间停顿

### 📚 知识库

- **文件夹结构** —— 像 Windows 资源管理器一样分类，支持子文件夹
- **自动分类** —— 新增条目按问题内容自动归类
- **同义词归一** —— "冰系"能命中"冷凝"，社区叫法和官方叫法都能搜到
- **群里自学** —— 群友发 `补充知识 问题 | 答案` 就能教它
- **全局条目** —— 群号填 0 表示所有群通用

### 🛡️ 群管

| 模块 | 能力 |
|---|---|
| 入群管理 | 入群请求审批、答题/超时验证、欢迎语、拒绝理由 |
| 风控 | 黑名单、广告拦截（硬词/软词/黑域名）、白名单 |
| 备份 | 定时自动备份、保留天数可调 |

> 签到积分 / 抽奖 / 群报现在都是**插件**，在「插件」页装卸。

### 🖥️ 管理界面

Web 控制台 + 原生桌面窗口（pywebview）：

```
概览 · 入群管理 · 风控 · 长期记忆 · 知识库
人格设定 · 语音合成 · 系统配置 · 调试 · 插件
```
- 实时日志流（带等级/模块筛选）
- 配置改完立即生效，不用重启
- **首次运行引导向导** —— 填几个空就能跑起来

#### 检查更新与下载校验（安全边界）

程序图标旁边显示当前版本；有新版会提示，点开能看更新说明、选下载线路、
就地下载（下到 `data/updates/`）。

**加速节点是第三方反代**，它有能力把下载到的 exe 换掉。所以走加速节点时
会强制核对 SHA-256，不通过就删文件。这里把校验的信任边界说清楚：

| 环节 | 来源 |
|---|---|
| 待下载的文件 | 加速节点（第三方）或 `api.github.com`（直连） |
| 期望的 SHA-256 | `SHA256SUMS.txt`，经 **`api.github.com`** 取，**不经过加速节点** |
| 它的**签名** | `SHA256SUMS.txt.sig`，**Ed25519**，私钥不在 GitHub 上 |
| 验签用的公钥 | 编译在本程序里 |
| 二者的比对 | 本机完成 |

**为什么要签名**：校验值和安装包如果都是同一个账号发的，拿到那个账号的人
可以**两个一起换** —— 哈希照样对得上。签名用的私钥**不在 GitHub 上**，
他签不出来。

**防得住**：

- 加速节点把 exe 换成别的
- 加速节点返回错误页 / 半截文件（实测遇到过一个节点返回 563 字节的 HTML 跳转页）
- 镜像链路上的传输篡改
- **发布者的 GitHub 账号被拿走** —— 换得了包，签不出签名

**防不住**：

- 跑发布脚本的那台机器被入侵（私钥在它上面，它就是信任根）
- GitHub 本身被攻破
- 私钥丢了又没有备份

**分级处理**（不是简单的"验不过就拒绝"）：

| 情况 | 行为 |
|---|---|
| 签名有效 | 用签名保护的哈希。**直连也比对**，否则投毒直连路径照样得手 |
| 没有签名文件 | 直连放行，但界面写明"无法排除发布账号被冒用"；加速节点拒绝 |
| 签名无效 | **一律拒绝下载**，不给"改用直连"的选项 —— 这时候两条路都不可信 |

**拿不到校验文件时，加速节点直接不可用**（宁可不可用，也不能装个没法验证的程序）。
想彻底不依赖加速节点就用「直连」。

下载完成后界面会显示实际算出的 SHA-256 和校验值来源，你可以自己去
Release 页面对一遍。

## 快速开始

### 方式一：下载桌面版（推荐）

1. 到 [Releases](https://github.com/Mario9800/nekoe/releases/latest) 下载 **`Nekolyra-desktop-vX.X.X.X.zip`**
2. 解压到任意目录（**整个文件夹要一起留着**，`_internal` 是运行库）
3. 双击 `Nekolyra.exe`
4. 按引导填：管理员 QQ、管理密码、机器人 QQ、AI Key
5. 完事，浏览器会自动打开管理界面

> ⚠️ 不要只拷 `Nekolyra.exe`，缺了 `_internal` 会启动失败。
>
> 📦 `Nekolyra-source-vX.X.X.X.zip` 是源码包，普通用户不用下
> （它是给开发者看的，同时也是 GPL-3.0 的合规要求）。

### 方式二：跑源码

```bash
git clone https://github.com/Mario9800/nekoe.git
cd nekoe
pip install -r requirements.txt
python bot.py
```

**依赖要求：**

| | |
|---|---|
| Python | **3.10 或更高**（开发和打包用的是 3.14，3.10 也测过） |
| 系统 | Windows 10/11（桌面窗口用 pywebview，其他系统只能跑 Web 管理界面） |
| 依赖 | 见 [`requirements.txt`](requirements.txt)：nonebot2 · FastAPI · uvicorn · httpx · pywebview |
| 其它 | 可选：Ollama（本地模型）、IndexTTS 2.5（语音） |

跑起来后浏览器打开 `http://127.0.0.1:8080/admin`（端口在 `config.json` 里改）。

### 还需要一个 QQ 协议端

Nekolyra 通过 **OneBot v11** 协议跟 QQ 通信，你需要另外跑一个协议端：

| 方案 | 说明 |
|---|---|
| [NapCat](https://github.com/NapNeko/NapCatQQ) | 推荐，基于 QQNT，比较稳 |
| [Lagrange.OneBot](https://github.com/LagrangeDev/Lagrange.Core) | 纯 C# 实现 |

装好后把机器人 QQ 和连接信息填进 Nekolyra 的 `.env` 或注册向导。
参考 [`config.example.json`](config.example.json) 和 [`.env.example`](.env.example)。

## AI 接口怎么选

### 免费方案（推荐）

**上海人工智能实验室「墨点计划」** —— 新用户送 10 墨点，1 墨点最多抵 500 万 tokens，够个人用很久。

```
API 地址   https://discovery-api.intern-ai.org.cn/v1
模型        deepseek-v4-pro-0813  /  deepseek-v4-flash-0731  /  glm-5.3 …
```

1. 到 [[intern-ai.org.cn]([https://intern-ai.org.cn](https://discovery.intern-ai.org.cn/)) ](https://discovery.intern-ai.org.cn/)微信扫码注册
2. 控制台创建 API Key
3. 填进 Nekolyra 的「系统配置」

**智谱** 也有免费模型：`https://open.bigmodel.cn/api/paas/v4`，模型填 `glm-4.7-flash`。

### 本地跑

装了 [Ollama](https://ollama.com) 的话，在「系统配置 → AI 后端」切到本地，
填 `http://localhost:11434` 和模型名（如 `qwen2.5:7b`）。不联网、不花钱，但效果看你的显卡。

### 其它兼容 OpenAI 协议的服务

地址填 `https://.../v1`，模型名填服务商给的即可（DeepSeek 官方、硅基流动、OpenRouter 等都能用）。

## 语音怎么开

语音是**可选**的，不开也能用，只是发文字。

需要另外跑 [IndexTTS 2.5](https://github.com/index-tts/index-tts)：

1. 部署并启动 IndexTTS 的 API 服务（默认 `http://127.0.0.1:7861`）
2. 在 Nekolyra 的「语音合成」页填入地址和 Key
3. 选音色、调情绪模式、试听

**性能提示**：IndexTTS 在 8G 显存的显卡上，如果 `settings.json` 里 `referenceDevice` 是 `auto`，
参考音频编码器会占用显存，生成一句 10 字的话可能要 **30 秒**。改成 `cpu` 后能降到 **3 秒左右**：

```json
{
  "referenceDevice": "cpu",
  "accelerationMode": "auto_safe"
}
```

（文件位置：`%APPDATA%\T8star-Aix · IndexTTS 2.5\settings.json`）

## 插件系统

### 装插件

管理界面 **插件 → 插件市场**，点「安装」。装好去「已安装」标签管理它：

```
停用 / 启用    配置    打开页面    卸载
```

- **配置** —— 弹出这个插件专属的配置小窗
- **打开页面** —— 插件自带的管理页（只有声明了页面的插件才有这个键）

想装市场上的插件就直接点；想装别人 GitHub 上的，把仓库地址贴在「已安装」页底部即可。

### 自己写插件

一个插件就是一个文件夹，最少两个文件：

```
my_plugin/
├── metadata.json    名称、版本、作者、配置项默认值
└── main.py          入口，def setup(ctx) 会在加载时调用一次
```

```python
def setup(ctx):
    @ctx.command("抽奖", "说明")            # 注册群命令
    async def h(event, cmd):
        await ctx.send_group(event.group_id, "回你了")
        return True

    ctx.register_page("myplugin", "标题", html)    # 插件自带页面
    ctx.register_config("我的插件", [               # 配置项（自己的小窗里）
        ["my_key", "设置项", "text"],
    ])
```

丢进 `data/plugins/` 下，管理界面点「重新加载」就能用，**不用重启**。

**完整文档**：[nekoe-plugins](https://github.com/Mario9800/nekoe-plugins) ——
`ctx` 能力全表、一个能跑的完整例子、容易踩的坑清单、可直接复制的骨架。

写完想被收录，提 PR 到 `nekoe-plugins` 改 `index.json` 就行。

## 常见问题

<details>
<summary><b>双击没反应 / 闪一下就没了</b></summary>

看同目录的 `startup.log`，里面会写原因。最常见的是 `_internal` 文件夹没跟着一起拷。
</details>

<details>
<summary><b>能连上 QQ 但机器人不回话</b></summary>

1. 管理界面「概览」看 AI 是否显示已连接
2. 「系统配置 → AI 后端」检查地址和 Key
3. 群里要 **@它** 或者叫它名字才会回（可在配置里改触发方式）
</details>

<details>
<summary><b>语音很慢</b></summary>

见上面「语音怎么开」的性能提示 —— 八成是 `referenceDevice` 没设成 `cpu`。
</details>

<details>
<summary><b>记忆好像没生效</b></summary>

记忆是**每 N 轮对话**分析一次才写入的，默认 4 轮。想让它记得更快，把「系统配置 → 长期记忆 → 分析频率」调小。

也可以在「长期记忆」页手动加一条，立即生效。
</details>

<details>
<summary><b>插件的页面在哪？侧边栏怎么找不到抽奖/群报？</b></summary>

插件页面**故意不占侧边栏** —— 不然装十个插件侧边栏就爆炸了。

入口在 **插件 → 已安装**，每张插件卡片上有「打开页面」。页面顶部有「← 返回插件」。
</details>

<details>
<summary><b>插件装上了但没反应</b></summary>

按顺序看这三处：

1. **卡片上有没有红色「加载失败」** —— 有的话把鼠标放上去看错误信息
2. **是不是「已停用」状态** —— 点「停用/启用」切回运行中
3. **命令要不要 @机器人** —— Nekolyra 的群命令默认都要 @ 它才触发

还不行就看「概览 → 实时日志」，插件报的错都带插件名。
</details>

<details>
<summary><b>装了插件，会不会偷我的数据？</b></summary>

**有可能。插件就是 Python 代码，跑在你电脑上，能用你的数据库和配置。**

所以：只装你信得过的来源。市场里带「已审核」标记的是我逐个看过的，
但收录也只代表"我看过一眼没发现坏心思"，不代表我给它背书。
</details>

<details>
<summary><b>换电脑怎么迁移</b></summary>

整个文件夹拷过去就行。配置在 `config.json`，数据在 `data/bot.db`，
插件在 `data/plugins/`，机器人账号在 `.env`。
</details>

<details>
<summary><b>端口 8080 被占了</b></summary>

改 `config.json` 里的 `port`，重启即可。桌面版会自动打开对应端口的管理界面。
</details>

## 隐私

- **数据全在本地** —— 数据库、配置、聊天记录都只存在你自己电脑上
- **只跟 AI 接口通信** —— 除了你配的 AI 地址，不往任何第三方服务器发数据

## 主题

**本项目的默认人格是「默认角色」。**

代码里的 `persona_*` 配置项可以直接改成任何角色或原创形象：

| 字段 | 说明 |
|---|---|
| `persona_name` | 名字 |
| `persona_identity` | 身份设定（它是谁、背负什么） |
| `persona_behavior` | 行为准则（什么时候回、怎么回） |
| `persona_speech` | 说话风格（长度、语气、忌用词） |

这四个字段留空就是「没有设定人格」，机器人会以中性语气回话。

> ⚠️ **关于版权**
> · **自己用 / 群里玩** —— 没问题，随便改
> · **二次分发 / 商用** —— 建议换成你自己的原创人格，避免版权纠纷

如果你只是想换个名字，改 `config.json` 里的 `persona_name` 就够了；想把整套设定换掉，四个字段一起改。

### 版本号与 tag 规则

版本号固定四段 `主.次.修.补`：

```
修 bug / 小改动       ->  只动最后一位      1.0.3.7 → 1.0.2.2
加了一组新功能        ->  动第三位          1.0.3.7 → 1.0.3.7
大改 / 不兼容         ->  动第二位          1.0.3.7 → 1.1.0.0
```

**打 tag 时四段必须写全** —— `v1.0.3.7`，不要写成 `v1.0.2`。
程序比对版本用的是四段元组（不足的补 0），三段的 tag 会被补成
`1.0.2.0`，跟 `1.0.3.7` 比就小了 —— 用户明明装了新版，程序却一直提示
有更新。这条靠约定规避，比在代码里猜"三段到底指哪个版本"可靠。

- **报 Bug** 请附上 `startup.log` 的相关片段
- **提功能** 先说清楚使用场景，比说"加个 XX"有用得多
- **改代码** 提 PR 前请跑一遍仓库里的三个检查脚本：

  ```bash
  python _check_ui.py      # 管理页 JS 语法 + 模拟 DOM 断言
  python _check_html.py    # HTML 标签配平与嵌套深度
  python _check_refs.py    # 悬空引用（删功能后最容易踩）
  ```

  改 `bot.py` 里的管理界面（`ADMIN_HTML`）时**务必跑 `_check_ui.py`** ——
  它抓过好几次"一处 JS 报错导致整个页面点不动"的问题。
- **写插件** 不用改主程序，见 [插件系统](#插件系统)。
  想被市场收录就提 PR 到 [nekoe-plugins](https://github.com/Mario9800/nekoe-plugins)
